# Iris Relay

Iris Relay 是跨 DCC、跨渲染器的材质转换项目。使用 MaterialX 保存材质功能、参数和连接，通过目标字典选择原生实现，让转换结果便于艺术家继续编辑，并改善材质外观的一致性。

系统只调整材质及其引用资源，不通过改变灯光、相机、曝光或色彩管理补偿误差。神经联合校正作为研究方向单独验证。

## 当前最重要的问题

当前最需要纠正的是转换的默认决策方式：遇到端口类型或参数差异，就倾向于拆解源计算，再用数学节点重新组合。即使目标软件已有艺术家常用的输出、节点或模式，也可能被跳过。

例如，粗糙度贴图需要一个单值。艺术家会先使用贴图节点已经提供该数据的输出，例如适用情况下的 `outAlpha`，直接连接粗糙度输入。如果工具忽略现成输出，默认重新读取 RGB、加权计算亮度，再建立转换节点，就把普通的材质搭建过程扩大成了公式重建。

颜色校正也一样：目标已有合适的颜色校正节点时，应先使用它的参数和模式，仅补必要差异。把源节点内部的全部公式复刻出来，会增加编辑成本、耦合源实现，也让后续维护围绕更多辅助节点展开。

**材质能创建、测试通过、公式能算出来，都不足以说明转换方式合理。转换结果还应该符合艺术家在目标软件里的正常搭建与编辑习惯。**

## 解决方向

默认按以下顺序决策：

**理解材质意图 → 采用目标软件的常规原生搭法 → 只补必要差异。**

1. **先判断数据用途。** 明确是在读取粗糙度等单值属性，还是作者有意做亮度、通道或其他计算。不能只看见 `color → float` 就决定增加转换。
2. **优先使用现成能力。** 从已有输出口、原生连接方式、节点模式和功能节点中选取合适表达。查资料和实机核对首先回答“正常工作流能否直接完成”；字典未登记不代表软件没有能力。
3. **字典先维护原生工作流。** 按 DCC、渲染器和节点系统记录常用输出、模式、连接规则及适用条件。交换文件保存功能、通用细节和关系，不预先决定目标必须创建多少节点。
4. **只补必要差异。** 先用原生参数表达差异，再考虑少量辅助。数学组合是原生工作流无法表达必要行为时的后备，由目标字典维护，导入时才展开；未应用细节保留并报告。
5. **按实际搭建结果验收。** 检查数据含义、原生可编辑性、辅助节点的必要性及失败边界。数值容差与近似需要依据，渲染外观需要对照证据，不把内部公式逐位一致设为默认目标。

具体准则、例子和迁移顺序见 [ADR-0014：以艺术家工作流选择目标材质表达](_docs/adr/0014-以艺术家工作流选择目标材质表达.md)。该决定补充 [功能交换与目标实现分离](_docs/adr/0012-功能交换与目标实现字典分离.md)及[按能力维护转换](_docs/adr/0013-按能力族推进转换与隔离宿主差异.md)。

## 当前状态

已具备独立 Python 核心、统一 API、声明式字典、MaterialX 文档处理，以及 Blender、Maya Arnold、C4D Redshift 的受限原生交换和界面。功能接口与目标实现的分离已部分落地，历史转换路径仍需按上述准则逐项审查；本次文档对齐不代表这些路径已经修复。

文件可保存、目标可转换和外观已验证分别报告，当前不承诺任意材质在任意渲染器中完全一致。历史批次与实验结果保留在 [文档索引](_docs/README.md)，不作为已完成本轮迁移的依据。

## 开始使用

需要 Python 3.11+ 和 uv，在仓库根目录执行：

```powershell
uv sync --extra dev
uv run python _examples/plugin_demo.py --transport python
```

示例验证 API 与源材质保护；宿主内使用见 [Blender／Maya／C4D 界面与操作步骤](_docs/unified-ui.md)。
