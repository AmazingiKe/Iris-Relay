# 可编辑 MaterialX 与跨宿主交换完善

日期：2026-11-11。本文记录本轮 C1–C5 的实际结果；首轮神经实验另行记录。重点是当前节点关系、贴图语义、可编辑性和兼容边界，结构通过不代表任意材质外观一致。

## 版本与结果

| 项目 | 实测版本／结果 |
| --- | --- |
| 文档核心 | MaterialX 1.39.5；公开 API v1 |
| 源与回导 | Blender 5.2.3 LTS／Cycles 5.2.3 |
| Maya | Maya 2022.5、Python 3.7.7、MtoA 5.3.5.3、Arnold 7.2.5.3 |
| Cinema 4D | 2025.3.2、Redshift 2025.3.0 |
| 字典版本 | Blender 0.4.0（123 个实现配置）、Maya 0.4.0（32 个）、Redshift 0.5.0（23 个） |
| A12 全量检查 | 1,801 个材质全部尝试；997 份标准／内联文档，804 份仅保留原生结构 |

标准文档比上一轮 688 份增加 309 份。997 份表示源图可表达为本轮标准／内联计算，不能解释为 997 份都能在任意目标创建。804 份保留文档明确标记不可转换，不能计入还原成功。共输出 1,801 份 `.mtlx`，原始 `.blend` 和贴图仍是完整恢复来源。

最终共同批次从全部 997 个候选中选择 50 个，覆盖 58 项选择特征；每个目标最多 1,000 个展开节点是本次批量选择预算，不是转换器固定上限。实际 Arnold 解码 AVIF 失败，因此批次显式排除 `.avif`；全量源报告仍保留这类文件，未将其伪装为已修复。

## C1：配方与源覆盖

- 可变 ColorRamp 配方生成标准 NodeDef／NodeGraph，单独输出 RGB 和 Alpha；实际 231 种源配置与 Blender 原生 `evaluate` 对照全部通过。包括 LINEAR、EASE、CONSTANT、B_SPLINE；不把它扩大为所有颜色模式均支持。
- 补充受限 Mix 模式、Gamma、Bright/Contrast、标准标量数学和 RGB 多输出。源配置进入配方摘要，目标重新生成并比较实际实现后才折叠回原生功能，不能只凭标签恢复。
- SDK 1.39.5 对部分嵌套多输出出口展开会丢失通道选择。子图内增加单输出恒等端点，保留明确输出选择；共享上游只创建一次。
- 命名法线 UV 必须有真实使用者证据。只在源网格等全部已读使用者确认其为渲染默认 UV 时允许默认切线基底展开；缺少或冲突证据返回 `NORMAL_UV_CONTEXT_REQUIRED`。目标几何须自行提供对应 UV，本项目不改几何。

全量阻断的首个原因如下；一个材质可能还有其他问题，不能按此推算修复某项后的成功数量：

| 首个阻断 | 数量 |
| --- | --- |
| 位移 | 301 |
| 未支持节点 | 108 |
| 未支持 MaterialX 输入 | 98 |
| 未支持 UV 来源／配置 | 74 |
| 命名法线 UV 证据不足 | 52 |
| 未支持原生节点模式 | 50 |
| 请求／原生图值边界 | 38 |
| 未支持色彩空间 | 38 |
| 其他（组默认值、类型、连接等） | 45 |

程序化纹理、非默认 Bump Strength、部分色彩 Mix、位移等仍按具体图阻断，原始信息留在报告与保留文档中。

## C2：RGBA、坐标与便携资源

RGBA 图片保留文件通道、Alpha 模式和颜色关联。五类 RGBA 夹具在 Maya、C4D 保存重开，另有 Blender 六类图片夹具；Maya／C4D 均完成当前图再导出。文件头、实际目标解码器和文档声明分别检查。

实际 Arnold 采样发现 PNG 的 `aiImage.outColor` 与 Alpha 关联，而 Raw RGBA EXR 的颜色独立。核心按目标字典生成显式颜色数学及独立 Alpha，零分母受保护；PNG 的量化、透明边缘过滤及零 Alpha 隐藏 RGB 丢失仍不能由反除完全恢复。非 Raw RGBA EXR 的探测异常，Maya 明确阻断。C4D Alpha 目前只有结构与声明式关联检查，始终报告 `RS_RGBA_SAMPLING_UNVERIFIED`；没有 Redshift 的 RGBA 外观成功结论。

Maya 命名 UV 与多步静态变换使用实际探测的 `aiUvTransform.uvwMatrix` 链，RGB 与 Alpha 处于同一坐标上下文，保存重开后读取当前矩阵再导出。额外真实渲染使用 `DetailUV` 加两步不可交换变换，经 Blender 导出和 Maya 公开入口还原：U、V 梯度相关系数分别约 0.999980、0.999998，内部区域 RGB MAE 约 `[0.000267, 0.000103, 0.002584]`；高频蓝通道与接缝仍受过滤差异影响，不宣称逐像素一致。默认 UV 也有独立梯度渲染核对，未反转 V。

C4D 二维 UV 采样器的实际参数读写、命名集和保存重开已验证；旋转次序与中心尚无渲染证据，报告 `UV_SAMPLER_CONVENTION_UNVERIFIED`。它是带明确边界的结构近似，不计外观验证。

公开资源操作为 `materialx.resources` 和 `materialx.rewrite_resources`。核心只处理文档；宿主公共工具按内容哈希复制文件、改写相对 URI、输出 manifest 并检查复制哈希。单文档资源包整目录搬移后，Maya 与 C4D 均完成导入、保存重开及路径核对。缺图须提供 URI → 现存文件的显式重定位映射，禁止按同名文件猜测。

```powershell
uv run python _scripts/package_materialx.py --source "已有材质.mtlx" --out "新的绝对资源包目录"
uv run python _scripts/package_materialx.py --source "缺图材质.mtlx" --out "另一个新目录" --relinks "显式重定位.json"
```

输出目录必须不存在。GUI 导入仍直接引用资源；需要便携交付时先运行此工具，再导入资源包中的文档。当前工具处理单份文档，不宣称完成多材质资产合集打包。

## C3：当前原生图与编辑后往返

Maya 与 C4D 均有独立、无 Iris 标记的原生小图验证：初始三节点两条连接，修改粗糙度并插入数学节点后，当前导出变为四节点三条连接；保存重开后仍读取当前值和当前拓扑。未知节点、未支持的额外出口保持阻断。

`identify` 的默认行为仍严格；适配器可显式请求字典声明的唯一 `source_default`，解决确有相同数值语义的多绑定歧义。已有实现提示必须与当前原生 ID 和模式重新匹配。原生再导出不重放导入 XML，不借源快照忽略用户编辑。

C4D 对当前材质的私有克隆展开功能组，原文档保持不变。实际 SDK 探测发现 `Ungroup` 不自动把未连接组输入的当前值传入子节点，读取前显式传播边界值；SDK 改写的节点 ID 与稳定身份单独记录，避免错误合并。

## C4：节点结构与编辑体验

核心保留作者标签、来源 ID、源位置和功能路径，按实际依赖补布局。自定义函数未连接的浮点／颜色接口创建一份共享控制；内部实现常量不会全部发布成作者参数。缺少原生常量绑定的窄目标以内联值继续转换，并报告 `EDITOR_CONTROL_LIMITED`。

| 宿主 | 实际编辑形式 |
| --- | --- |
| Blender | 节点标签、整理框、源位置或拓扑布局；超过原生 63 字符的逻辑 ID 单独保存，当前编辑仍可读回 |
| Maya | 原生 container、功能名、发布属性与共享控制；最终批次 254 个功能容器、162 个发布参数 |
| C4D | 原生功能组、边界连接、共享控制留在外层保持唯一身份；由原生编辑器自动布局 |

Maya 面板的“查看节点与共享参数”打开实际 Node Editor，侧栏直接编辑发布的原生属性。已在 Maya 2022 前台会话观察并截图；ColorRamp＋Mix 四个夹具的发布参数修改、保存重开、当前回读与再次导出均通过。

这不承诺恢复所有源 DCC 的完全相同组类型、界面或像素位置。计算展开后的图可能较大，功能分组与共享控制用于提高可读性；不能把节点多作为支持更多语义的证据。

## C5：外部文档与兼容层次

从 [MaterialX v1.39.5 官方 StandardSurface 样本](https://github.com/AcademySoftwareFoundation/MaterialX/tree/v1.39.5/resources/Materials/Examples/StandardSurface) 取得 22 份原始文件，保留 URL、SHA-256，不修改样本来迎合支持范围。

| 入口 | 实际结果 | 证据边界 |
| --- | --- | --- |
| Iris Relay → Blender | 7 / 22 创建并保存重开 | 其余明确阻断 |
| Iris Relay → Maya | 7 / 22 创建、保存重开、当前再导出 | 节点、参数、连接和资源检查 |
| Iris Relay → C4D Redshift | 7 / 22 创建并保存重开 | 其余明确阻断 |
| MtoA 原生 `arnoldImportAss` MaterialX 路径 | 22 份均创建表面；18 份具有可比较常量且全部相符 | 未核对复杂上游全部拓扑、资源或外观，不等于 22 份完整还原 |
| C4D 原生 `MergeDocument` 文件加载器 | 0 / 22 创建材质 | 仅此加载入口，不推断所有其他 MaterialX 插件能力 |

已知全局 `lin_rec709` 上下文可保留线性数值；未知全局颜色上下文仍拒绝，不靠调整目标场景色彩设置消除错误。

`capabilities` 增加通道、坐标和实现能力摘要，标记 `dictionary_declaration`，宿主预检仍必需。`materialx.diff` 比较节点定义、实现声明、有效默认值、连接／输出选择、URI、颜色和 Alpha；可给显式节点对应表。它不比较纹理像素、不证明任意图同构或外观等价。

## 问题与解决记录

| 实际问题 | 处理与仍存边界 |
| --- | --- |
| 多输出经 SDK 展开丢选择 | 子图内单输出端点；增加选择与共享关系回归 |
| Arnold PNG 与 EXR 的关联不同 | 格式分开声明、显式 Alpha 数学、真实 EXR 探测；非 Raw RGBA EXR 仍阻断 |
| C4D 二维值类型无法当普通列表读写 | 依实际 SDK 类型读取 x/y；保存重开核验；着色器次序仍提示未验证 |
| C4D 展组丢当前接口默认值 | 私有克隆中显式传播值，再展开读取，不改原材质 |
| 功能默认值被数学展开淹没 | 保留一份共享作者控制，三端提供原生编辑形式 |
| Blender 截断长逻辑 ID | 单独保存稳定 ID，读取当前根图时恢复并检测冲突 |
| Maya compound 发布属性自动生成子属性 | 按实际原生命名与绑定核验，侧栏使用真正的属性控件 |
| 特殊字符导致 SDK 序列化 XML 无法再读 | 有界 XML 转义后由 SDK 重读并比较等价，失败不输出 |
| AVIF／WebP 在当前 Arnold 解码器失败 | 宿主明确阻断；结构批次与训练清单按实际资源预检限定，不改名冒充支持 |
| Redshift 最小渲染返回失败 | 64×64 发光球返回 code 1（`RENDERRESULT_OUTOFMEMORY`），日志含 `RenderContext.cpp(2928)` 断言；释放本任务验证 GUI 后重试仍失败。该枚举不足以判定物理内存耗尽，未改用户安装或许可；结构结果与外观分开，本轮训练使用已许可的 Arnold |

本机产物根目录名为 `iris-relay-overnight-20261111-01`，绝对路径保存在任务状态与本机报告，不作为仓库配置提交。关键目录：

- `blender-from-maya-final-03/`、`c4d-native-final-02/`、`blender-from-c4d-final-03/`、`c4d-from-maya-final-02/`：当前原生图跨端结果。
- `maya-groups-final-06/`、`c4d-group-probe-03/`、`c4d-transactions-final-01/`、`maya-editor-ui-04/`：接口编辑、SDK 问题、事务及实际界面证据。

核心自动回归、源哈希最终复核和分批提交的完成状态以[验收清单](overnight-acceptance-20261111.md)为准。未覆盖其他 DCC 版本、任意着色器／位移、动态坐标、UDIM、完整原生组重建与任意灯光条件下的外观一致性。首轮神经模型也不会自动扩大这些边界。
