# 按能力维护材质转换

依据 [ADR-0013](adr/0013-按能力族推进转换与隔离宿主差异.md)，维护入口是失败证据和功能契约。功能交换与目标实现继续遵循 [ADR-0012](adr/0012-功能交换与目标实现字典分离.md)。以下工具已实现，直接从仓库根目录运行，不依赖打开 DCC。

## 从报告建立影响集

指定已有批次 `summary.json`，或单份核心／宿主控制层报告。输出必须为新目录：

```powershell
uv run python _scripts/analyze_material_failures.py --reports "报告目录/summary.json" --out ".local/问题分析-新编号"
```

可以在 `--reports` 后提供多个报告。批次只读取同目录中与案例 ID 对应的详细 JSON，不递归混入其他作业。工具兼容 Blender 控制层、公共宿主文件流程、公开 API 响应和原生保留汇总；不支持的结构、损坏 JSON、重复记录和目标冲突须先处理，不能据空结果声称没有问题。

输出 `analysis.json` 包含：

- `groups`：按阶段、错误码、原消息、节点类型、实际模式、端口、环境和字典指纹组织的候选组。`family_hint` 只按错误码提供领域提示，不能据此认定根因或最终责任模块。
- `affected_cases` 与 `cases`：通过引用关联全部受影响案例，保留来源路径及目标；同一案例的多个问题不会重复计算失败案例数。同一诊断在摘要和核心响应重复出现时只计一次；不同批次中的案例仍各自保留，不推定为唯一资产数。
- `evidence_gaps`：未取得节点类型、阶段或诊断等证据的缺口。XML 来源的节点类型不在此工具中猜测，宿主读取早期失败也可能没有可重放请求。
- `inputs`：本次所用摘要和详细报告的 SHA-256。来源报告只读，复测前核验旧报告没有改变。
- `coverage: observed_only`：只统计报告里已观察到的问题；不能把首个阻断数量当作全部根因数量或修复后新增成功数。

有充分请求数据的分组另存 `replay-分组ID.json`。它保留完整来源，是待复验的代表请求，**没有自动最小化，也没有自动确认与原始宿主失败等价**。缺少来源或目标时不生成请求，不从原生快照猜测一份材质。

## 修复与复测

先复验代表请求，逐步去掉无关图结构并确认原问题仍在，为该能力建立最小夹具。预期语义来自功能契约、API 证据或独立参考；相同错误码只是定位线索。然后确定修改归属：

| 证据 | 修改位置 |
| --- | --- |
| 原生标识、模式或端口绑定有误 | 字典及其生成来源 |
| DCC 的真实读写、动态接口、创建或撤销有误 | 对应 `plugins/<host>/` |
| 类型、连接、功能含义或上下文表达有误 | 相应核心流程或功能规则 |
| 目标没有适用实现 | 目标字典的原生映射或辅助／替代配方 |
| 结构正确但外观不同 | 固定条件的渲染对照与有证据的材质校正 |

已有 `recipes.py` 的配置编译器和端口映射集中登记，源绑定与目标配置处理共同调用；新增普通绑定无需为每对 DCC 编写转换器。新增配方仍须明确契约和证据，不允许字典执行任意 Python。

修复后通过公开 API 复测影响集：

```powershell
uv run python _scripts/analyze_material_failures.py --reports "报告目录/summary.json" --out ".local/影响集复测-新编号" --recheck
```

可加 `--group "分组ID"` 选择一个候选组，重复该选项选择多个组；ID 应来自相同旧报告生成的分析。`--dictionaries "字典目录"` 可显式选择待验证规则，默认使用仓库运行时字典。

`recheck.json` 的 `scope` 为 `core_only`：每个影响案例只请求一次，保留当前警告／错误和 `still_observed_groups`。原诊断消失后可能出现新阻断，仍须检查当前完整结果。CLI 成功退出仅表示分析或复测流程完成，不表示所有材质转换通过；判断转换结果要读取逐例 `status` 和 `issues`。新图不由此写入 DCC。

`not_replayable` 的案例仍在影响集中，应在对应宿主重新读取、创建或执行事务检查。核心复测不能替代这些步骤，也不能替代渲染。阶段验收再运行适当的完整回归与受影响宿主检查。

## 检查依赖边界

```powershell
uv run python _scripts/check_dependency_boundaries.py
```

检查实际 `iris_relay/` 和 `plugins/` 的绝对、相对导入及字面量动态导入：核心不能依赖宿主运行时、插件或开发脚本；插件使用已有公开模块；不同宿主不能相互导入，公共插件流程不能依赖某个宿主。违规时报告路径、行号、模块和规则并返回非零退出码；此检查也包含在 pytest 中。

这是依赖方向检查，不能证明任意公式没有复制，也不解析由变量计算的动态模块名。规则是否重复、目标图是否膨胀，仍须在差异审查中结合契约与图规模判断。

## 首个去重试点

本轮选择了代码中有明确重复证据的“可变配置”能力，不声称它是全部资产的最高频失败。渐变与命名法线原来在源配置和目标功能配置两条路径分别选择编译器、维护端口映射；现在共用同一份显式登记，来源的 UV 所有者证据和目标字典授权仍分别核验。

本地改造前后通过同一公开服务比较两类导出及六组转换，完整结果相同：

| 能力 | Blender 核心节点数 | Maya Arnold 核心节点数 | C4D Redshift 核心节点数 |
| --- | --- | --- | --- |
| RGBA 渐变 | 2 | 26 | 43 |
| 命名切线法线 | 2 | 4 | 4 |

这些是本轮夹具的核心图规模，不含宿主另建节点；渐变的目标数学图仍较大，去重不等于节点压缩。此次没有改变计算公式、目标覆盖或引入新的外观结论。宿主保存重开证据沿用 ADR-0012 已登记范围，本次没有重新生成 DCC 场景。

历史 C4D 当前图再导出的五份真实报告共观察到 15 条警告，归为三个候选组；复测五份核心请求后原警告仍存在，如实保留。它验证报告读取与影响集闭环，不是修复了 15 个 bug 的证据。本地产物位于忽略目录 `.local/capability-maintenance-01/`，不提交原场景、贴图或大体积报告。

本轮 888 项完整回归通过；最后两项工具边界补充后，57 项工具复验通过，覆盖当前 894 个不同测试。生产核心覆盖率 90.41%，两项工具合计 86%；Ruff、格式和依赖检查通过。完整回归版本与后续仅工具变更的核对见同目录 `validation/final-evidence.json`，不将不同生产核心版本的结果混算。
