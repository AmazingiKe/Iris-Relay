# 三宿主统一材质交换界面

Blender、Maya 和 Cinema 4D 使用相同的操作顺序与状态含义，保留各自原生控件。界面共用 `plugins/presentation.py` 的连接检查、状态文字和报告摘要；材质规则仍由公开 `RelayService` 提供，界面不复制转换逻辑。

## 操作布局

1. **服务连接**：选择自动、本地核心或 HTTP 服务，点击“检测连接”。HTTP 模式可以填写服务根地址。
2. **导入／导出**：三端按同一顺序显示操作页。
3. **01 选择来源**：导入选择 `.mtlx`；导出选择当前原生材质及输出位置。
4. **02 检查与执行**：先“检查材质”，确认警告后“导入为新材质”或“导出 .mtlx”。检查不会创建目标材质或写文件，真正执行时会重新读取当前输入。
5. **03 结果报告**：默认显示可读结果；按需展开详细诊断或 JSON，并可复制完整报告。

“检查通过”不代表已经导入或保存；只有实际创建或写入成功才显示“已导入”“已导出”。带警告的成功仍保留警告标记，阻断优先显示失败。源材质不会被默认替换，已有 `.mtlx` 不会被覆盖，外观一致性仍需单独验证。

切换连接、修改输入或发生受支持的场景历史事件时清除旧报告；每次执行仍重新检查当前材质，不依赖界面的历史成功状态。原生图的任意外部修改不等于已经完成新的检查。

## 连接方式

| 选项 | 行为 |
| --- | --- |
| 自动 | 保留原有默认策略；若配置了 `IRIS_RELAY_HTTP_URL`，使用该 HTTP 服务 |
| 本地核心 | 明确使用本机核心，不受 HTTP 环境变量影响 |
| HTTP 服务 | 使用面板中的地址，默认 `http://127.0.0.1:8765` |

检测连接查询真实能力，核心需要 MaterialX 1.39.5。连接失败不静默切换后端；修改面板选项不会修改进程环境变量。关闭或重新加载面板时只释放自己持有的本地会话，不关闭共享 HTTP 服务。

HTTP 服务需要另行启动，见 [HTTP 使用说明](http.md)。本轮保留同步操作方式，不把服务端工作线程称为宿主异步界面；Maya 批量操作可以取消尚未开始的后续文件。

## 宿主入口

### Blender 5.2.3 / Cycles

在文本编辑器运行 `_examples/blender_demo_gui.py`，文本编辑器或 3D 视图的 N 侧栏打开 **Iris Relay**。入口原地运行可自动定位仓库。

导出页可直接选择材质或“使用活动材质”。“仅导出表面（排除位移）”仍是显式选择。导入页每次处理一份文件，新建材质不自动绑定对象。连接区与报告详情可折叠，窄侧栏可以滚动查看。

### Maya 2022 / Arnold

在 Python 脚本编辑器运行：

```python
import runpy
runpy.run_path(r"仓库路径/_examples/maya_demo_gui.py", run_name="__main__")
```

导入页支持添加多个文件或目录、检查选中项及逐文件新建材质。保留“选中已导入材质”和“查看节点与共享参数”。导出页读取场景或 Hypershade 中选中的 `aiStandardSurface`，选择输出目录后逐材质保存；摘要中列出实际输出位置。

### Cinema 4D 2025.3.2 / Redshift 2025.3.0

在脚本管理器运行 `_examples/cinema4d_demo_gui.py`，或通过 `runpy.run_path` 运行该文件。打开的是会话内原生窗口，不安装永久插件。

导入页选择一份 `.mtlx`，检查后创建新材质；导出页使用材质管理器当前选中的材质，并选择新的 `.mtlx` 路径。当前窗口只接入已验证的 Redshift 适配器，不把其他渲染器显示为受支持目标。

## 开发与验证入口

- `_tests/test_presentation.py`：摘要状态、连接能力检查、失败回收、本地模式和只检查导出。
- `_tests/test_cinema4d_ui.py`：当前文档、连接切换和报告失效。
- `_scripts/verify_blender_gui.py`：独立后台 Blender 的原生按钮与文件流程。
- `_scripts/verify_maya_panel_ui.py`：独立 Maya GUI 的面板操作与真实截图。
- `_scripts/verify_cinema4d_ui.py`：独立 C4D 的控制流程与原生材质核验；GUI 布局需另外在真实窗口检查。

验证使用独立进程和新建测试目录，不在用户当前场景执行破坏性测试。截图及原生场景留在本机输出目录，不进入仓库。

## 本轮验证与修正记录（2026-11-11）

| 宿主 | 已验证内容 |
| --- | --- |
| Blender 5.2.3 LTS | 本地 19 组、真实 HTTP 20 组原生操作检查；导入、导出、警告确认、缺图阻断、保存重开及连接切换；前台侧栏截图检查 |
| Maya 2022.5 / Arnold | 原生窗口的本地与 HTTP 连接、只检查无写入、真实导出和新建材质、禁止覆盖、报告复制；正常及窄窗口截图检查 |
| Cinema 4D 2025.3.2 / Redshift 2025.3.0 | 本地控制链路实际导入、保存重开、当前原生再导出、撤销重做及源资源保护；分别核验常量和带图片材质，图片样本保留 2 个计算节点、1 张贴图、2 条连接和 1 个功能组；另行打开真实窗口检查两页布局 |

修正了 Maya 窄窗口的连接按钮裁切，并将 HTTP 地址移到独立行，仅在 HTTP 模式显示。Blender 改为按中英文显示宽度折行，连接区和详细报告可折叠。C4D 原生 `AddCheckbox` 需要完整尺寸参数，缺失时会导致布局只生成一半；补齐参数后在实际 GUI 核对，不能用后台 SDK 检查替代窗口验证。

报告生命周期也做了针对验证：Maya 在修改来源、手输或浏览输出目录、重新检测连接时同步清除旧报告和成功统计，9 项原生回归通过。C4D 的材质预览会递增 `DATA` 脏标记，因此 Redshift 图使用实际图修改戳判断；导入报告不依赖当前选中材质，导出报告仍依赖选择。真实 GUI 已核验自动预览后报告保留、改变图参数和撤销后报告失效。

公共控制、宿主控制和传输相关的 90 项针对性回归通过；C4D 最后调整后的 10 项单测另行复跑通过。Ruff、格式检查、Git 差异及文档链接检查通过。未重复执行整个材质转换测试集，本轮未修改转换规则。

本轮没有扩大材质转换范围，也没有新增渲染外观结论。三端仍使用各宿主原生控件，因此字体、边框和控件尺寸随宿主主题及系统缩放变化；统一的是操作顺序、用语、分区和结果含义。
