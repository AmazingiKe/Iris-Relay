# ADR-0003：原生节点绑定与宿主验证

- 日期：2026-11-04
- 状态：已采纳（真实字典与受限验证链路）
- 关联：[ADR-0002](0002-统一插件接口与初步核心实现.md)
- 2026-11-11 后续决定：[ADR-0010](0010-共享字典与运行时接口兼容检查.md)替代第 2 项强制软件精确版本匹配；下文保留当时的决定及理由。

## 背景

参考字典证明了统一协议，但没有具体软件的节点名称、资产 ID 或整数 code，无法指导宿主读写。同一渲染器在不同 DCC、插件版本和节点系统中使用不同标识。用户要求补全字典，并允许在本机软件中验证。

## 决定

1. 分开存储完整探测目录与可执行转换字典。目录尽量记录当前安装版本可发现的类型、端口及失败信息；只有已定义语义与边界的条目进入转换字典，不以收录数量代表转换覆盖率。
2. 渲染器引用增加 `host`、`host_version`、`node_system`，三个字段须一起提供。字典匹配渲染器及宿主的精确版本。旧示例继续使用不带宿主的引用。
3. 字典增加声明式 `native` 绑定，保存节点／端口 ID、整数 code、宿主属性和数值编码。禁止字典携带脚本或任意可执行转换函数。
4. 统一 API v1 增加 `describe`，插件通过它获取绑定与指纹；语义转换仍只在核心执行。支持可逆 `scale`、`scalar_to_color`，非恒等连接仍需显式实现，当前阻断。
5. 原生默认控制项可显式标记 `omit_if_default`；仅当未连接且值等于已核验默认值时省略，保留源快照和信息记录。非默认或未知语义继续阻断。未使用的已知输出可省略，参与图的输出不得丢失。
6. 首批核验 Blender 5.2.3、C4D 2025.3.2 中 Redshift 2025.3.0 和 Arnold 7.4.3.0／C4DtoA 4.8.3.1。每端实现标准表面、图片与切线法线基础映射。范围与证据见[原生字典文档](../native-dictionaries.md)。
7. 宿主验证使用独立临时测试文档，保存、重开并读回参数与连接。验证的文件与日志留在忽略目录，Git 只提交可复现脚本、字典及结果说明。

## 替代方案

- 只存节点显示名：不能稳定调用 API，也无法区分同名节点，拒绝。
- 将不同 DCC 的 code 混在单一 renderer 键下：易误写端口，拒绝。
- 一次性把目录中所有节点都标记为支持：没有语义映射和验证证据，拒绝。
- 让插件各自保存映射：违背统一核心 API 的要求，拒绝。

## 后果与限制

真实节点绑定可查询并经过宿主结构验证，新增宿主需要明确版本、编码及端口能力。标准材质之间仍可能出现明显的外观差异，统一名称和成功读回不证明 BSDF 等价，转换报告继续保留近似警告。

Blender 提供实验性脚本适配器，C4D 当前提供集成验证写入与核对，不代表完整生产插件已完成。原生颜色编码目前限定已核验上下文；OCIO／ACES、任意 UV 变换、层材质、程序化图、非默认 SSS／透射及神经校正仍需后续证据。

## 未决问题

正式插件形态、C4D 现有图的无损导出与交互撤销、更多节点的组合转换、跨上下文色彩处理、渲染误差指标及训练数据仍待验证。不能通过改变用户场景灯光、相机、曝光或色彩管理解决材质转换误差。
