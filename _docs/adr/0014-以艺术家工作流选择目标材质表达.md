# ADR-0014：以艺术家工作流选择目标材质表达

- 日期：2026-11-12
- 状态：已采纳（转换决策与行为准则；现有路径的迁移及验证尚未完成）
- 关联：[ADR-0004](0004-统一节点功能定义与原生实现选择.md)、[ADR-0008](0008-可编辑图与贴图语义交换.md)、[ADR-0012](0012-功能交换与目标实现字典分离.md)、[ADR-0013](0013-按能力族推进转换与隔离宿主差异.md)
- 调整范围：补充目标实现的选择依据，将艺术家在目标软件中的常规原生工作流作为默认方案，数学重建作为有明确缺口时的后备。保留原决定的历史理由和验证结果。

## 背景

当前最重要的问题是转换决策偏向内部计算复刻：看到源与目标的端口类型、参数或计算细节不同，就拆解源计算，再用数学节点组合出结果。这样可能绕过目标软件已经提供的常用输出、原生模式和功能节点。

这不是简单的节点数量问题。艺术家在目标软件中通常先判断贴图或材质功能的用途，再选合适的输出口、参数和连接方式。转换器如果从源软件内部公式出发，就容易把普通操作扩大成一张计算图。结果即使通过结构或数值检查，也可能难以理解、编辑和维护。

ADR-0012 已分离功能交换与目标实现，ADR-0013 已明确能力与职责边界。但把公式移到字典，或者仅对少数高层节点设置原生优先，还不足以纠正普通连接与数据读取中的同类倾向。需要统一决策顺序及验收依据。

## 决定

### 1. 先按艺术家的搭建过程理解材质

默认顺序为：**理解材质意图 → 采用目标软件的常规原生搭法 → 只补必要差异。**

首先判断所需的是属性数据、颜色处理、通道选择，还是作者有意建立的运算。依据来自源连接、贴图用途、节点设置和已确认的工作流；不能只凭文件名或端口类型猜测材质意图。

随后回答：“艺术家在目标软件里会怎样用现成节点、输出口和参数完成这件事？”查资料、读 API 和做实机核对，都先服务于这个问题，而不是首先寻找展开源公式的方法。复用已有证据，缺少的事实再核对；普通搭建时的数据确认不应扩大为每条连接的内部公式证明。

### 2. 按目标原生工作流选择表达

按适用条件依次考虑：

1. 已有输出口与原生连接方式，包括经确认能承接所需语义的隐式转换。
2. 原生参数、模式或功能节点。
3. 原生节点加少量必要辅助，只补当前不能直接表达的部分。
4. 目标字典维护的数学替代；没有合理实现时明确报告支持边界。

“少量辅助”不设统一的节点数阈值，而要求每类辅助都对应明确的必要差异；不能把完整公式重建换个名称归入辅助层。

“字典没有映射”和“目标软件没有能力”是两种情况。尚未登记时，先检查目标的正常用法，不直接据此生成数学图。节点名称相同或连线能建立也不足以证明适用，需要确认相关输出实际提供所需数据。

选择以材质用途、原生可编辑性和已有证据为依据。既不默认追求内部公式逐位一致，也不单纯追求节点数量最少；必要差异和已知近似按既有策略报告，不能静默改变材质含义。

### 3. 将准则应用到普通连接

| 情况 | 首先采用的思路 | 数学辅助的使用条件 |
| --- | --- | --- |
| 单值属性贴图接粗糙度等输入 | 使用已经承载所需数据的单值输出，例如适用配置下的 `outAlpha` 或分量输出，直接连接 | 现有输出与原生模式不能表达所需数据或必要运算 |
| 颜色校正 | 使用目标的原生颜色校正节点、参数和模式 | 已确认有必要行为无法由原生功能表达，仅补该差异 |
| 类型转换或通道选择 | 先检查目标已有输出、接收端口和转换模式 | 当前连接方式确实不能承接所需语义 |

以粗糙度为例，若现有单值输出已经承载这张数据贴图的粗糙度值，就直接使用它，不默认取 RGB 再建立亮度加权与转换节点。确认输出是否承载该数据，是艺术家正常搭建时的数据检查。`outAlpha` 不是无条件代表粗糙度的固定规则；真实透明度也不能被当作粗糙度。

若作者明确进行亮度运算、选择特定通道或使用自定义权重，则这些是材质语义的一部分，应按意图表达。不能把所有颜色转单值都归为读取 Alpha，也不能凭节点名删除作者原有数学图。这里纠正的是转换器默认添加辅助计算的倾向。

### 4. 字典记录工作流，交换文件保存功能

目标字典首先维护该 DCC、渲染器和节点系统的正常表达：可用输出、节点模式、连接方式、适用条件、已知差异与依据。允许复用已有规则和配方生成器，不为每对软件建立一套转换表，也不为本决定预建新的通用框架。

MaterialX 继续优先复用官方功能定义，保存参数、通用细节和连接关系。交换层显式表达一种转换语义，不代表目标必须额外创建一个可见转换节点；能由已有输出或原生模式承接时，应直接采用对应工作流。

数学替代仍按 ADR-0012 由目标字典维护，仅在导入时展开，不写成新交换功能的默认实现。未应用细节保留并报告；主要功能无合理表达时，按现有协议阻断当前材质转换并保留源信息。源图与资源保持可恢复，不通过修改场景条件掩盖差异。

### 5. 调整实现行为与验收方式

开发者与自动化代理在实现一类转换前，应能简短说明：

- 该材质功能或连接在表达什么用途。
- 艺术家在目标软件中通常怎样完成，现有原生能力是否适用。
- 为什么需要新增辅助，各类辅助具体补什么必要差异。
- 采用了哪些依据，哪些已知近似或路径尚未处理。

用户指出策略偏差时，先复查决策顺序及同类能力路径，不能只解释现有公式为什么能计算，或者仅修补被点名的实例。发现能力缺口时按 ADR-0013 归入相应职责，再做最小验证和影响集回归。

验收除语义、参数和连接外，还需检查目标图是否保留正常的原生编辑方式，是否存在可由现成输出或模式承接的重复辅助。测试通过、材质创建成功、把数学节点放进分组或节点数量下降，都不能单独证明该准则已落实。外观效果仍须有固定可比条件下的渲染证据。

## 迁移顺序

1. 先完成 README、文档入口及协作准则的对齐，清楚区分决定与已实现能力。
2. 后续按连接或功能族审查现有生成路径，记录正常原生搭法、实际缺口和当前选择，不先全量拆解或重写适配器。
3. 选择一个有明确原生工作流的代表问题做最小迁移；确认必要行为、原生编辑与失败边界，再复测影响集。
4. 将证据补入目标字典及对应报告，保留历史实现理由。阶段性扩大验证范围，未迁移路径继续明确说明。

## 替代方案

- 默认完整复刻源公式：容易绕过现成工作流，增加节点与维护成本，不作为默认方案。
- 只把所有公式移入字典或分组：改善存放位置，没有解决实现选择的起点问题，不足以满足本决定。
- 所有单值贴图一律接 Alpha，或仅凭节点名称替换：忽略数据实际含义，不能作为通用规则。
- 无条件选择节点最少的图：可能改变作者有意的运算，不能代替语义判断与验证。

## 后果

实现工作会先投入目标软件常规用法的确认与规则复用，再补能力缺口。预期结果是更接近艺术家日常使用的原生材质图；现有路径是否变得更易编辑、节点是否减少、外观是否改善，仍须迁移后验证。

字典与核心的分层继续保留。此决定调整默认推理顺序和实现选择依据，不要求删除一切数学节点，也不承诺不同渲染器的内部运算或外观完全一致。

## 实施记录与未决问题

本轮完成文档和行为准则的对齐，尚未修改转换代码、目标字典或宿主读写。现有亮度与类型转换等路径仍需后续审查；既有批次的结构、数值和宿主验证不能作为该迁移已经完成的证明。

后续需明确各能力的原生适用条件、可接受近似与验证范围。规则应复用现有字典机制；只有实际接口不足时才单独设计兼容增量。外观改善与长期维护收益继续分别积累证据。
