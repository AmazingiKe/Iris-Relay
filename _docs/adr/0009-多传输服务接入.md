# ADR-0009：多传输服务接入

- 日期：2026-11-11
- 状态：已采纳
- 关联：[ADR-0002](0002-统一插件接口与初步核心实现.md)、[ADR-0005](0005-MaterialX材质图核心与自定义节点扩展.md)
- 依据：用户确认 Python API 与 HTTP 是同一服务的可选调用方式，并要求实现独立服务接入目录。

## 背景

现有进程内与 JSON 子进程接口已共用业务协议。多个 DCC 的 Python 版本及依赖不同；共享独立核心进程可以统一字典、MaterialX 环境与可选模型的加载。ADR-0002 首版暂不引入 HTTP 的条件现已变化，原历史理由保留。

## 决定

1. 保留 `RelayService.handle(request) -> response`。进程内 `RelayAPI`、JSON 子进程客户端和 `HttpRelayService` 提供相同业务请求响应，插件不复制转换与校正规则。
2. 新增 `iris_relay/server/`：`app.py` 负责 FastAPI 传输接入；`runtime.py` 负责启动配置、字典与可选模型实例和执行生命周期；`__main__.py` 提供模块启动入口。服务通过公开 `RelayAPI` 调用核心。
3. 客户端 `iris_relay/http_client.py` 保持 Python 3.7 与标准库兼容，不导入服务端、MaterialX 或训练框架。FastAPI 和 Uvicorn 是 `http` 可选依赖。
4. `POST /v1/handle` 接受现有请求对象并返回现有响应对象。业务失败保持 HTTP 200，调用者必须检查 `status`；传输失败使用非 200 状态。`GET /health` 只报告就绪状态。
5. 首版默认回环地址 `127.0.0.1:8765`，启动器拒绝非回环监听；不提供远程鉴权、TLS 部署或资源上传。拒绝浏览器 Origin 和非回环 Host，请求与响应均限制 16 MiB，客户端不代理、不重定向、不自动重试。
6. 一个服务实例复用一份字典和可选预测器，工作线程串行执行核心。已有业务执行时返回 503，不无限排队。断连不会提前释放仍在执行的核心槽位，停止服务等待已接受调用完成。
7. 宿主保留原有默认调用方式。设置 `IRIS_RELAY_HTTP_URL` 时显式选择 HTTP，连接失败明确报告，不静默换用另一个后端。读取、创建、绑定与撤销仍归宿主适配器。
8. 贴图路径沿用现有资源语义；HTTP 不复制本机文件。模型只从服务启动参数加载，仍受原实验上下文和失败回退约束；加载模型不代表开启每次转换的校正。

## 替代方案

- 只保留进程内和子进程：可继续使用，但不能满足此次增加 HTTP 调用方式的需求。
- 为 HTTP 另建业务 DTO、转换服务和模型规则：拒绝，容易造成调用方式之间的语义分歧。
- 每个 DCC 内安装完整服务依赖：拒绝，增加宿主版本冲突。
- 首版引入任务队列、远程资源仓库和公网部署：暂不采用，没有当前场景的验证与部署需求。

## 后果

插件可使用同一核心进程，服务部署与宿主环境分离。HTTP 增加了服务启动、端口冲突、网络错误和忙状态，需要清晰报告。服务端后台执行不等于宿主界面已异步化，现有同步 GUI 流程保持原状。只增加接入方式，不增加材质支持范围或证明视觉效果。

## 未决问题

远程服务的认证、TLS、文件上传／路径映射，以及批量作业调度和宿主异步界面，需要后续独立确定范围。现有同步核心没有强制中断接口，客户端超时不等于取消服务端计算。

## 验证

验证入口为 `_tests/test_http_client.py`、`test_http_server.py`、`test_http_plugin.py` 和 `test_http_e2e.py`，覆盖真实本机 HTTP、原协议一致性、插件选择、并发与失败路径。操作说明及实际验证记录见 [HTTP 服务](../http.md)。
