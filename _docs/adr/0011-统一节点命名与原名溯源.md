# ADR-0011：统一节点命名与原名溯源

- 日期：2026-11-11
- 状态：已采纳
- 关联：[ADR-0005](0005-MaterialX材质图核心与自定义节点扩展.md)、[ADR-0006](0006-未知原生图保存与目标组合转换.md)、[ADR-0008](0008-可编辑图与贴图语义交换.md)
- 用户确认：中文转拼音，标点和表情删除，开头数字删除；无法转写时使用 ID，清理为空时使用节点类型名；所有节点只保存一份原名备份，平时不使用。

## 背景

MaterialX 的合法名称处理会把汉字变为下划线，多个名称容易混淆。Maya 的实例名也不能直接沿用中文。此前原名还会自动复制到显示标签、来源 ID 等字段，往返导出可能用处理后的名称覆盖最初来源。

## 决定

1. 核心增加 `iris_relay/naming.py`，集中负责当前节点名的语言处理、清理、长度及冲突处理。`pypinyin==0.55.0` 只安装在核心环境；宿主通过既有公开服务获得处理结果，不各自安装拼音库或复制规则。
2. 删除标点、空白、表情和其他符号，保留字母、数字与下划线；删除开头连续数字，包括全角数字。汉字转无声调拼音，保留英文和中间、末尾数字。最终名称只包含 ASCII 字母、数字及下划线，不以数字开头。下划线作为合法名称字符保留。
3. 无法转写的文字使用当前协议 ID；ID 本身也不合法时使用 `node_` 加稳定 SHA-256 摘要。清理后为空或仅有下划线时先使用节点类型名，类型名仍不合法则退到稳定 ID 摘要。不是按拼音反查节点，也不把日文假名等猜测为中文。
4. 名称上限为 63 个 ASCII 字符。合法既有名称优先保留；清理、同音或截断产生的冲突按稳定身份分配摘要后缀并实际检查唯一性。相同输入不因节点列表顺序改变而改名。所有连接端点及材质出口同步重映射。
5. 原生协议使用节点 `metadata.source_name`，MaterialX 使用节点 `iris_source_name`，二者是同一备份在不同协议中的表示。初次处理即保存，包括无需改名的节点；已有备份沿链路传递，不随当前重命名更新。导出的主图、内联子图、辅助节点及材质根节点均有该字段；生成节点记录其生成时名称。
6. 备份不作为名称生成、连接匹配或默认显示标签的来源。停止自动生成重复的 `editor.source_id` / `source_label`，迁移时清除与当前或原始实例名相同的旧副本。独立编辑标签、功能路径和来源位置继续保留，不等于原名的额外备份。
7. Blender 在节点自定义属性 `irisSourceName` 保存原文；Maya 的同名字符串属性保存 ASCII JSON 字符串；C4D 在材质用户数据“原始节点名”表中按节点 ID 保存 ASCII JSON 映射。实测 Maya ASCII 场景和 C4D 字符串会损坏部分非 BMP 字符，因此不能直接写入表情原文。
8. Maya 使用核心给出的实际节点名。场景中已有同名节点时，由宿主分配唯一实际名称并用返回值接线；不覆盖已有节点。C4D 的计算节点名称采用核心 ID，显示层不再用原名替换。Blender 继续使用核心 ID。
9. 原生保留文档使用 `iris_snapshot_index` 对应完整快照，不再额外复制 `iris_native_id` 名称。快照原始身份和失败响应中的源图继续保留，以满足源信息不可丢弃的要求。验证器兼容旧文件字段。
10. 内联实现校验只排除明确的编辑及溯源属性；内部节点名称在副本中按相同规则比较，兼容旧文件的数字开头名称。计算常量、端口、连线和实现声明仍严格比较，不能用来源名字伪装计算相同。

## 替代方案

- 全部中文替换成下划线：无法阅读且容易冲突，不采用。
- 每个宿主单独处理：会产生不同名称并增加映射复杂度，不采用。
- 用中文标签代替实际节点名：不能解决 Maya 实例名称和统一连接身份的问题，不采用。
- 每次都从备份名重新生成：会覆盖用户后续重命名并破坏备份的被动职责，不采用。
- 只保存拼音或从拼音恢复原字：同音与多音字不可逆，不采用。

## 后果与验证

`convert`、`materialx.export`、`materialx.convert` 和 `materialx.preserve` 的节点名遵循此规则；外部文档转换后的节点 ID 可能不再含原先的层级斜线，调用方应使用返回的节点和端点。原文仍在响应 `source` 中。`materialx.normalize`、资源改写和差异比较保持各自的文档操作职责，不强制重命名外部文档。

`_tests/test_naming.py` 覆盖中文、中英混合、数字开头、标点、表情、其他语言、空名、长度、重名、遍历顺序、特殊字符编码、原生保留文档、子图连接以及多次转换。`_scripts/verify_node_names.py` 从 `IRIS_NAMING_JOB` 读取作业，在独立宿主中导入两次、保存重开、读取当前图并再次导出；作业包含 `host`、新建的 `out` 目录和 `documents` 路径列表。本机输出留在 `.local/naming-01/`，不提交场景和日志。

2026-11-11 验证：全量 795 项通过；随后增加原生保留顺序与旧内联节点名两项回归，相关 31 项及 64 项检查通过，共覆盖当前 797 项测试。核心覆盖率 91%，命名模块 95%；Ruff 检查及格式检查通过。Blender 5.3.0、Maya 2022／Arnold 7.2.5.3、C4D 2025.3.2／Redshift 2025.3.0 各四个材质通过重复导入、保存重开、当前图读取和再次导出，原名中的中文与表情完整保留。Maya 宿主代码与验证入口通过 Python 3.7 语法检查。

## 未决问题与边界

拼音使用库的词组读音，不保证符合每个资产作者的多音字习惯；原文可按需溯源。这里只做汉字转写，不提供所有语言的拉丁化。完全丢失溯源元数据的外部软件无法恢复最初名字。本轮验证节点、参数连接和保存重开，不新增渲染外观结论。
