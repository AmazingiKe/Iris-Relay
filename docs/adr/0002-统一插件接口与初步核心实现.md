# ADR-0002：统一插件接口与初步核心实现

- 日期：2026-11-04
- 状态：已采纳（初步工程实现）
- 关联：[ADR-0001](0001-材质转换与神经校正架构.md)
- 确认的新增需求：核心提供抽象接口，所有插件使用同一 API。
- 本文确定初步工程组织，不将神经校正的研究假设改为已验证结论。

## 背景

项目需要从架构文档进入可运行的初步构建，同时尚未确定首个 DCC 和真实渲染器转换方向。若插件分别实现规则或直接调用核心内部模块，后续统一校正、兼容性和错误处理会变得困难。

## 决定

1. 使用 Python 3.11 及以上版本实现独立核心，运行时仅依赖标准库。核心不导入任何 DCC 模块，暂不引入机器学习框架。
2. 以 `RelayService.handle(request) -> response` 作为抽象服务接口，`RelayAPI` 是进程内实现。插件只依赖公开服务、材质协议和接入辅助接口。
3. 提供相同 JSON 协议的命令行传输，`JsonCommandService` 实现跨进程客户端。插件可以调用独立 Python 核心，避免要求宿主内置 Python 加载核心及未来训练依赖。首版不引入 HTTP 服务。
4. API 版本、材质模式版本、字典内容版本、渲染器版本分别标识。API v1 包含能力查询、校验和转换；拒绝未知字段和版本，不静默猜测。
5. 核心实现原生材质图到语义图、再到目标材质图的双阶段转换。支持声明式节点和端口映射、显式默认值、标量和向量范围、同类型连接，以及 `identity` / `one_minus` 数值变换。
6. `one_minus` 等非恒等变换作用于连接时，必须使用显式变换节点才能保持含义。首版尚未提供自动插入操作，因此阻断该类转换并保留源信息。
7. 建立联合校正扩展协议。预测器一次接收完整源图、语义图、目标图和字典版本，返回一组输入修改；只有字典允许、未被连接驱动且满足类型和范围的修改才能整组应用。该协议为未来模型提供接入位置，不是训练模型或外观优化结果。
8. 插件辅助接口默认只新建无警告的目标材质，不自动更换场景绑定。失败回滚及宿主撤销由真实 DCC 适配器实现；核心接口不能替宿主保证这些行为。

## 初步构建范围与证据

| 内容 | 验证方式 |
| --- | --- |
| 可安装核心包和公开 API | 构建 wheel，在独立环境运行 API 与命令行 |
| 材质图、资源引用和源信息保留 | 节点、贴图、混合层连接及往返转换测试 |
| 声明式字典与转换报告 | 未知节点、范围、默认值、版本冲突及无损失败测试 |
| 插件共用 API | 同一参考插件分别通过 Python 与子进程传输运行 |
| 联合校正扩展与回退 | 协议测试预测器验证整组应用、异常和非法提案回退 |
| 中文开发文档与目录规范 | README、API 文档、ADR、AGENTS 和中文 Git 提交 |

`reference.gloss` 与 `reference.rough` 是明确构造的参考配置，只用于验证协议、连接保留及可逆数值操作；不对应 Redshift、Arnold 或 Cycles，不用于推断真实渲染效果。示例贴图 URI 是内存资源标识，不是附带的贴图文件。

## 替代方案

- 每个 DCC 自带转换实现：拒绝，会分裂语义与校正逻辑。
- 只提供 Python 函数调用：不采用为唯一方式，宿主语言和 Python 版本可能不同。
- 一开始部署 HTTP 常驻服务：暂不采用，当前没有远程访问需求；未来可在同一协议外增加传输适配层。
- 从真实渲染器映射开始猜测参数：不采用，需要确认转换方向并依据对应 API、版本与渲染证据逐项实现。
- 先训练网络再定义协议：暂不采用，当前缺少训练数据和真实渲染基线。

## 后果与限制

初步核心和参考插件可独立运行，但不能直接转换用户现有 DCC 场景。真实渲染器字典、宿主插件、贴图派生操作、自动插入转换节点、神经模型训练及渲染评价闭环仍是后续工作，不能因为协议测试通过就宣称已实现。

首版校正输出仅支持已有数值或向量输入，不能重写拓扑或贴图。输入上下文保留完整图关系，后续新增贴图重映射、节点组合等操作时，须定义对应约束和测试，并维护 API 版本兼容性。

命令行每次调用启动一个核心进程，优先验证接入一致性，暂不保证批量转换性能。接入真实 DCC 时还需明确宿主单位、色彩约定、节点默认值和资源定位规则。

## 未决问题

首个 DCC 与转换方向、真实渲染器版本、运行时性能目标、神经模型特征表达与训练数据，继续按 ADR-0001 的未决项推进。
