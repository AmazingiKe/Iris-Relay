# ADR-0004：统一节点功能定义与原生实现选择

- 日期：2026-11-05
- 状态：已采纳（统一语义层与受限宿主验证）
- 关联：[ADR-0002](0002-统一插件接口与初步核心实现.md)、[ADR-0003](0003-原生节点绑定与宿主验证.md)

## 背景

现有字典使用 `texture.image` 等语义名称，但缺少集中定义和端口契约；一份字典禁止多个原生节点归入同一语义。相同原生节点的不同模式可能实现高度凹凸或切线法线，仅按名称不能识别功能。用户确认需要统一功能定义，降低宿主之间成对维护映射的成本。

## 决定

1. 核心集中维护版本化功能契约，通过公开 `semantics` API 查询。首批规范图片纹理、高度凹凸、切线法线，并登记既有标准表面属性。契约包含含义、输入输出类型、必要端口、限制及标准参考；原生 ID 仍在宿主字典中。
2. 新字典声明 `semantic_schema_version: "1"` 并校验契约。旧协议示例不自动解释为新契约，以免把测试中的任意参数名冒充正式语义。
3. 字典节点键表示一个确定的实现配置。多个键可以共享 `native.id`，用声明式 `native.properties` 区分模式。适配器读取这些属性，经统一 `identify` API 决定实现；不在插件复制识别规则。缺失模式、未知配置或多重匹配均报错。
4. 多个来源实现允许归入同一功能。目标只有一个实现时直接使用；有多个时须显式指定唯一 `target_default`，否则转换阻断并保留源图。不得依赖字典遍历顺序选择目标。目标不支持源参数或连接仍按既有规则报告，不因默认选择静默丢弃。
5. 核心继续执行两阶段转换，宿主仅处理读写。节点 ID、端口、默认值和原生 code 从探测目录获取；功能语义和不同实现的近似边界仍需人工核验，不使用名称相似度猜测。
6. `bump.height` 处理标量高度场，`normal.tangent` 处理编码法线颜色；图片用途由连接和资源色彩解释共同表达。为验证真实图片驱动高度的链路，增加最小 `channel.red` 功能，显式提取 R 通道；不能把 Alpha 当成亮度，不能把 RGB 隐式变成高度。其他通道尚未覆盖，已有的非 R 连接不能静默替换。
7. 第一轮仅承诺结构与参数链路。高度尺度、导数、切线与几何体相关的外观差异保留近似警告，独立渲染对照才能支持外观结论。

## 标准评估与替代方案

- USD/UsdShade：适合材质图交换，Sdr 能查询已注册节点；原生节点的发现与语义仍需集成提供。UsdPreviewSurface 的节点集合不覆盖完整高度凹凸工作流，因此不把它作为唯一功能集合。
- MaterialX：标准 `image`、`normalmap`、`bump` 可作为功能划分依据，但类型、坐标、单位及原生实现必须逐项核验。本轮记录参考关系，不声称已兼容 MaterialX 文件或执行语义，也不引入运行时依赖。
- 每个宿主单独维护全套成对规则：重复且容易分歧，不采用。
- 根据显示名自动猜测：无法区分模式和第三方节点，不采用。

依据：[UsdShade](https://openusd.org/dev/api/usd_shade_page_front.html)、[UsdPreviewSurface](https://openusd.org/release/spec_usdpreviewsurface.html)、[MaterialX 标准节点定义](https://github.com/AcademySoftwareFoundation/MaterialX/blob/main/libraries/stdlib/stdlib_defs.mtlx)。

## 后果

新增宿主只需补充原生到通用语义的绑定，不必为每个已有宿主增加成对转换。节点 ID 和参数可自动探测，功能对应、支持配置和差异规则仍是必要的集中维护内容。新功能元数据须与核心版本一起分发；词汇相同不等于渲染等价。

实现证据：核心 API 测试覆盖功能契约、多个来源实现、模式缺失与歧义、默认目标选择和失败保留源图；三套字典可从探测目录重复生成。6 组源材质和 18 组目标转换完成实机保存重开验证，包含图片驱动法线及显式 R 通道驱动高度的链路，详见[验证范围](../native-dictionaries.md)。未进行渲染外观对照。

## 未决问题

USD/MaterialX 实际导入导出、按参数能力选择多个目标实现、跨渲染器高度单位和幅度校正、更多通道与通道组合、更多原生模式与生产插件仍需独立证据与后续实现。
